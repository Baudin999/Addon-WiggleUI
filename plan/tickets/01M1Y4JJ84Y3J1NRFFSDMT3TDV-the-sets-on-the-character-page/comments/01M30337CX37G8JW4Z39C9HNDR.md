Landed at 6b5cb292. ./scripts/check.sh at zero.

SetRow.lua holds the circle row, the toggle stack, the gestures and the store watcher; Paperdoll.lua only hosts them. SQUARE is the disc now and the row height is Pane:Tall(), which Natural, Resize, the row pitch, the column sizes and the figure all read.

Five decisions worth not re-deriving.

The toggles could not go at the page's literal top left. That corner is the first two rows of the left gear column and a 36 px disc there lands on two secure squares. The stack takes its height off the top of the page instead, Natural asks for it and Resize centres the rows in what is left, so a page with one set moves down by the stack. The row height promise is kept exactly: zero sets changes nothing, one set grows no row.

A true diagonal slash is not drawable here. SetRotation turns a texture inside its own rect, so a rotated fill is a clipped rectangle, and the addon ships no slash art. Deliberately empty is a 2 px bar across the ring, which is unmistakably not the hollow ring.

Circle to circle is a copy, not a move. OnDragStart lifts without clearing and OnDragStop clears only when UI.Carry.Land found no taker.

Circles and toggles are built on the first repaint that needs one, never at build. Three circles on twenty rows is sixty buttons a set-less character would never see, and it dodges the frame level trap: rows are raised over the model after they are built, so a circle made at build would sit under the figure and lose the cursor to it.

The store watcher calls CharWindow.Fit only when the set count changes, then paints. Every Capture is a write and refitting on each one would be the page flinching every time you save a bracer.

Fixed at the merge: the spec icon lookup probed C_SpecializationInfo from this tree and only Core may probe. It is ns.SpecArt in Core now. Routing it through ns.TalentRead instead would have raised that allow-list count, which scripts/ratchet.lua refuses.
