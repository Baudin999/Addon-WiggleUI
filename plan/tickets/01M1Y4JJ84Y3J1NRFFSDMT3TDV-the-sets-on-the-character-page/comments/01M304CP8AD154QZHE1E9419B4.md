The feature shipped unreachable at 6b5cb292: no set meant no toggles and no circles, nothing on the page made one, and the only way in was /wui set save, a command the player was never shown. The empty toggle at the foot of the stack is drawn whether or not a set exists, and it opens a window rather than naming the set for you.

The window is UI.Window, not UI.Ask. Ask is a yes or no about a sentence, and a text field and a tick box bolted onto it would be two windows wearing one name. A name field opening on Spec.Label with the text selected, one tick box reading as a positive, start from what you are wearing, ticked by default, and an accept refused while the name is empty or taken with the reason on the window rather than after the press. Unticked makes every slot unset, which is how a five piece resist set is built: add the five and the set leaves the other fourteen alone.

Two decisions the next reader would otherwise re-derive.

The refusal does not go through Sets.New. New answers its reason by being called and the call that does not refuse has already written the set, so a dry run would say the name was taken over a set it had just made. A local Wanted() trims, refuses empty and asks Sets.Get. New is still called on accept.

Escape had to be overridden on the field. UI.Field clears focus on escape and UISpecialFrames only sees the second press, which reads as a stuck dialog. The override is on this one edit box; UI/Widgets.lua was not touched.

The circles draw from the first set rather than the second. Waiting for the second was backwards: one saved set you are not fully wearing is the case the circles exist for. A character with no sets still opens the page that shipped, to the pixel.
