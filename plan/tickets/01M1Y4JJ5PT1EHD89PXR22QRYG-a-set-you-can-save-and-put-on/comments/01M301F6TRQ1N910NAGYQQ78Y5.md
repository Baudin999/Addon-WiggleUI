Dual spec changes this card's weight. The client has two talent groups (see
01M301EPSBHQZFFKP9PBSED0B4), so a set is a thing you put on nightly rather than
once a raid, and the epic's line about phase 5 being the weakest is wrong.

A set carries one field the epic does not have: `group`, the talent group it
follows, nil for a set with no spec behind it. A resist set and a PvP set are
real sets with no group, so the row of sets is never capped at the number of
talent groups. Only two of them can carry a number.

The API is a contract, because the page card is written against it in parallel
and a rename is a merge conflict in two trees.

    ns.Sets.All()               array of records, display order
    ns.Sets.Get(name)           record or nil
    ns.Sets.Entry(name, slot)   "item" | "empty" | "unset", link
    ns.Sets.Active()            the set whose group is the active one, or nil
    ns.Sets.Wearing(name)       every entry matches what is worn

    ns.Sets.New(name)           record, or nil and a reason
    ns.Sets.Remove(name)
    ns.Sets.Rename(old, new)
    ns.Sets.Capture(name, slot) what is worn goes in; slot nil is all nineteen
    ns.Sets.Put(name, slot, link)
    ns.Sets.Empty(name, slot)   deliberately empty
    ns.Sets.Clear(name, slot)   back to unset
    ns.Sets.Follow(name, group)
    ns.Sets.Undo()              one level

    ns.Sets.Wear(name)          false and a reason if refused
    ns.Sets.Swap(group)         talents, then the set that follows them
    ns.Sets.Watch(fn)           told on every write, the shape UI/Scan.lua uses

A record is `{ name, group, slots }` and `slots[slot]` is a table for an item,
`false` for deliberately empty and nil for unset. The item table is
`{ key, link }`, the key being fields 2 through 8 of the link as the card body
already argues.

Swap order is not negotiable: talents first, wait for the event, gear second.
The talent switch is a cast, the gear queue is a server round trip per item,
and running them together is how a set lands half on.
